## Goals / Non-Goals

**Goals:**
- 客户端**重连**时,服务端精确补发其空窗期(`event_id > Last-Event-ID`)的事件,覆盖「最近 N 条列表」可能漏掉的范围。
- 租户隔离、补发有上限、对无 `Last-Event-ID` 的连接零行为变化。
- 零 schema、零持久游标表(复用 `event_id` 作游标 + 浏览器 `EventSource` 自带 `Last-Event-ID`)。

**Non-Goals:**
- 服务端持久 per-subscriber「已投递游标」表(跨完整后端重启、且期间无任何客户端连接时仍能补)。
- 多实例 live fanout(Redis pub/sub)——独立 follow-up;但注意重连补发因走共享 DB,跨实例**重连**本就可用(见 Risks)。
- 精确一次投递保证;超过上限的更旧历史补发(由列表 API 兜底)。
- WebSocket。

## Decisions

**D1 — 游标来源:客户端 `Last-Event-ID`(SSE 标准),而非服务端持久 per-subscriber 游标表。**
- 理由:SSE 原生——浏览器 `EventSource` 在自动重连时**自带** `Last-Event-ID`(值=最后收到帧的 `id:`);`event_id` 是严格单调 IDENTITY,配 `(kindergarten_id, event_id)` 唯一索引可高效做 `> lastId` 查询。零 schema。
- 备选(服务端持久游标表):需持久化 subscriber 身份 + 投递时写游标 + 回答「多客户端时谁推进游标」,更重且语义不清;弃,记为 follow-up(覆盖「所有客户端离线 + 后端重启」的极端空窗)。

**D2 — 补发有上限 `detection.sse.replay-max`(默认 200)。** 空窗 > 上限时补发**最近**上限条(升序末段),更旧的由前端列表 API 兜底。防止长期离线客户端触发巨量补发。

**D3 — 补发位置:connect 时,register 之后,同步发往该新 emitter,再接实时。** 有界 N 条同步发送在请求线程可接受;升序发送使客户端最终停在最新。补发用 `try/catch` 包裹,失败即 evict(与实时帧一致)。为此 `register` 返回该 emitter,controller 拿到后调 `sseService.replaySince(kgId, lastId, emitter)`;抽出私有 `sendEvent(emitter, vo)` helper 供实时与补发共用。

**D4 — 租户隔离。** 补发查询严格按**连接者活动园** `kindergarten_id` 过滤;`Last-Event-ID` 仅作数值下界,跨园 `event_id` 因园过滤天然取不到,无法越权。

**D5 — 健壮性:缺失/非数字 `Last-Event-ID` → 不补发。** 不报错,连接退化为现状(`connected` + 实时);非数字静默忽略。

**新增查询:** `DetectionEventRepository.findByKindergarten_IdAndIdGreaterThanOrderByIdAsc(Long kgId, Long lastId, Limit limit)`(Spring Data `Limit`)→ `DetectionEventService` 包一层返回 `List<DetectionEventVO>`(租户从安全上下文/参数取,与 `getForPush` 同风格)。

## Risks / Trade-offs

- **[长期离线 → 巨量补发]** → D2 上限封顶;更旧由列表 API 兜底。
- **[重复投递:列表 API 历史 + SSE 补发重叠]** → 客户端已按 event id 去重(现有「de-duplicate by event id」),且 SSE `id:`==列表 `event_id`,无重复渲染。
- **[`event_id` 作投递序]** → IDENTITY 保证按插入序单调;即便事件 `detected_at` 乱序,补发按 `event_id`(=插入序=投递序),正是「你错过了什么」的语义。
- **[多实例]** → live fanout 仍需 Redis(follow-up)。但**重连补发**走共享 DB:客户端重连到任一实例,凭 `Last-Event-ID` 都能从 DB 补齐——故本 change 在未来多实例下对「重连补发」这一面**已可用**,只剩 live 增量推送的跨实例 fanout 待补。

## Migration Plan

无 schema 迁移。纯增量代码 + 配置 + 测试。回滚 = 还原改动;无 `Last-Event-ID` 路径行为不变,无数据影响。
