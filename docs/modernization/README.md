# 演进与现代化（Modernization）

## 用途

本目录承载**系统演进视角**的内容：当前状态的客观评估、技术债与风险的清单、需要人工确认的开放问题，以及未来工作的登记。它回答"**这个系统现在处于什么状态，哪些地方需要关注**"。

> ⚠️ **重要边界（Discovery 模式）**：本目录**只做客观记录与提问，不提供解决方案、不做设计、不下处置结论**。技术债与风险均作为**事实**陈述；如何取舍由团队在 Design 模式下通过 ADR 决定。本知识库建立时的任务明确要求"不提出解决方案"。

## 与其它目录的关系

- 各架构/工程/运维文档中的 ❓ 标注，都在 [open-questions.md](open-questions.md) 汇总并编号（如 `OQ-SEC-1`）。
- 要**改变**现状（修债、补功能），应进入 **Design 模式**并产出 [ADR](../decisions/adr/README.md)，而非在本目录直接写方案。

## `CLAUDE.md` 使命对照

> "这是一个长期生产系统……每次改动都应优化长期演进：保持业务正确性、提升可维护性、降低技术债、保持架构可理解。"
> "一次贡献只有在保持系统稳定的前提下，至少做到下列之一才可接受：改善理解、改善可维护性、交付业务价值。"

本目录服务于"**改善理解**"——把现状与风险摊开，为后续决策提供依据。
