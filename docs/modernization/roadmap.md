# 演进路线（Roadmap）

> ⚠️ **本文档当前是占位（placeholder）。**
>
> 按知识库建立时的约定与 Discovery 模式，此处**不提供解决方案、不排优先级、不下设计结论**。路线图的实际内容需要：
> 1. 团队对 [open-questions.md](open-questions.md) 逐项确认（澄清意图与目标态）；
> 2. 在 **Design 模式**下评估备选并产出 [ADR](../decisions/adr/README.md)；
> 3. 由决策者确定优先级与节奏。

## 它将来应包含什么

待团队对齐后，本文档可演进为：

- **主题域**：按"安全强制 / AI 闭环 / 测试基线 / 运维成熟度 / 数据一致性"等组织。
- **每项关联**：对应的 `OQ-*` 开放问题与（一旦决策）对应的 `ADR-*`。
- **状态**：未开始 / 进行中 / 完成，及负责人。

## 如何推进（流程提醒）

任何具体工作启动前：

1. 选定一个**单一目标**的会话（`CLAUDE.md` 会话规则）。
2. 引用相关 ADR / 开放问题。
3. 若涉及重大决策 → 先在 Design 模式产出 ADR，评审通过后再 Implementation。
4. 保持改动小、可独立评审、仓库始终可工作。
