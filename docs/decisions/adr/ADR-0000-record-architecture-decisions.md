# ADR-0000: 采用架构决策记录（ADR）

## 状态

Accepted

## 背景

本项目此前**没有**显式记录架构决策。代码能展示"是什么"，但"为什么这样做、放弃了哪些备选、有哪些约束"散落在贡献者记忆中。随着团队从 3 人收缩为 1 人维护（根 `README` 记载，2026-05-11 起），这些隐性知识面临流失风险。

`CLAUDE.md` 已将 ADR 列为最高优先级的事实来源，但目录尚未建立。

## 决策

采用轻量级 **ADR** 记录重大架构决策，存放于 `docs/decisions/adr/`，遵循统一模板（[adr-template.md](adr-template.md)）与流程（[../README.md](../README.md)）。

同时，对**已固化在代码中的既有决策**，以"回溯性 ADR"（`Accepted (Retrospective)`）形式补记，以便新人理解系统的来龙去脉。

## 后果

- **正面**：决策有据可查、可追溯、可演进；新人上手门槛降低。
- **代价**：需要纪律去维护——重大变更必须同步新增 ADR。
- **影响范围**：全体贡献者与本知识库。

## 考虑过的备选

- **不记录，靠代码与口口相传** — 团队收缩后不可持续，已被否决。
- **用 Wiki/外部工具** — 与代码分离易过期；ADR 随仓库版本化更贴近代码。
